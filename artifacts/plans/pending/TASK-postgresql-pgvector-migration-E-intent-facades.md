# Task: Intent Facade Adaptation

## Problem Statement

Parts C and D created PostgreSQL repository classes replacing all ArangoDB AQL operations. The three intent facades (`LibraryDb`, `MlDb`, `AppDb`) and their maintenance companions still import and delegate to the old AQL operations classes. This plan re-wires all five facade classes to use the new repositories instead. Public method names and logical contracts are preserved; internal delegation, types, and async/sync characteristics change as a necessary consequence of the database migration.

**⚠️ BLOCKED status resolved:** The pre-requisite contract gaps noted below have been resolved via Plan C/D amendments. `FileStateRepository` and `EmbeddingStreamRepository` are now fully specified in Plans C and D respectively. All repo-layer methods (truncate, delete, bulk operations) are created in Plans C/D; this plan only delegates to them.

**Scope clarification:** This plan creates **facade methods only** — thin wrappers that delegate to repository methods. All repository methods (including `truncate_*`, `delete_*`, `search_files_by_tag_contains`, `list_all_tag_names`, etc.) are created in Plans C/D. Plan E steps show the delegation pattern: `await self._repo.method()` not repo method creation.

## Dependencies

- **Part C** (Domain Repositories — Core): provides `LibraryRepository`, `FileRepository`, `FolderRepository`, `TagRepository`, `ScanRepository`, `AppRepository`, `PipelineRepository`, `FileStateRepository`
- **Part D** (Domain Repositories — ML & Navidrome): provides `VectorRepo`, `ModelRepo`, `OutputRepo`, `CalibrationRepo`, `NavidromeRepo`, `EmbeddingStreamRepository`

## Type System Changes

The database migration necessitates three systematic type changes across all facade methods. These are not optional — they are physical consequences of replacing ArangoDB with PostgreSQL:

| Aspect | Before (ArangoDB) | After (PostgreSQL) |
| --- | --- | --- |
| ID parameters | `str` (document `_id` like `"libraries/12345"`) | `int` (auto-increment PK) |
| Return types | `dict` / `Document` / `list[dict]` | DTO dataclasses (`LibraryRow`, `LibraryFileRow`, etc.) or `None` |
| Method sync/async | Synchronous | `async` (SQLAlchemy `AsyncSession` requires it) |

Callers in services/workflows/interfaces are updated in Part F to match these type changes. This plan only changes the facade internals.
